# LinkedIn post

1. Establish what was **actually implemented**: check git log, ADRs and the solution source. Ask the user
   which language to write in (Polish or English).
2. Structure (max ~200 words):
   - Hook: one concrete technical lesson, not a generic statement.
     Good: "The important part of error handling in Power Automate wasn't catching errors. It was making failures observable."
   - Problem, then solution and architecture in 2–4 sentences.
   - A trade-off or something that did not work.
   - Lesson learned.
   - Optional link to the repo or the relevant ADR.
3. Rules:
   - It is a **portfolio project**. Never imply production usage, real customers or a team.
   - No exaggeration, no buzzword stacking, at most 3 hashtags, no emoji walls.
   - Avoid "Power Platform is amazing!"-style content.
4. Show the draft to the user. Do not publish anything.
